## 一、大白话讲核心概念

### 1. HTTP 是什么

**HTTP = 浏览器和服务器之间约定好的"对话规则"。**

你去餐厅吃饭，你跟服务员之间有一套默认的交流方式：
- 你坐下 → 服务员过来
- 你点菜 → 服务员记下来
- 后厨做菜 → 服务员端上来
- 你吃完 → 你买单走人

HTTP 就是浏览器（你）和服务器（餐厅）之间的**那套交流规则**。

全称：**HyperText Transfer Protocol（超文本传输协议）**

### 2. HTTP 的工作流程

```
浏览器 ←———HTTP 请求———→ 服务器
（你）                      （餐厅）
```

每次访问一个网页，背后都是：

1. **浏览器发请求**（Request）："服务器，我要看这个页面"
2. **服务器处理**：找到对应的资源
3. **服务器返回响应**（Response）："好的，这是你要的东西"

**一个关键特点：请求-响应模式**
- 必须是浏览器先说话（发请求）
- 服务器才会回话（返回响应）
- 服务器不会主动找浏览器聊天

**类比**：你打电话订外卖——
- 你打电话（浏览器发请求）
- 店家接电话（服务器收到）
- 店家说"好的，30 分钟到"（服务器返回响应）
- 通话结束
- 店家不会在你不打电话的时候主动打给你

### 3. HTTP 的特点

| 特点 | 白话解释 |
|------|---------|
| **简单快速** | 浏览器只发一个请求，服务器就返回结果，不啰嗦 |
| **无状态** | 服务器不记得你是谁——你每次访问，它都当你是陌生人 |
| **灵活** | 可以传文本、图片、视频、JSON 等各种格式 |

**无状态**这个很重要，举个例子：
- 你第一次访问淘宝 → 服务器不认识你
- 你登录了 → 服务器验证通过
- 你点"我的订单" → 服务器**又不认识你了**，因为你刚才登录的信息它没记住

那为什么还能正常用呢？因为后面会用 **Cookie、Session、JWT** 等技术来解决"记不住人"的问题（后面课程会讲）。

### 4. 你在 day02 的项目里，其实已经在用 HTTP 了

```
浏览器访问 http://localhost:8080/hello
     ↓
浏览器发了一个 HTTP 请求（GET /hello）
     ↓
Tomcat 收到 → Spring 处理 → HelloController
     ↓
服务器返回 HTTP 响应（状态码 200，内容是 "hello world"）
     ↓
浏览器显示 "hello world"
```

**整个过程都是按照 HTTP 的规矩来的。**

## 二、生活类比总结

| 概念 | 餐厅类比 |
|------|---------|
| HTTP 协议 | 餐厅里顾客和服务员之间的"规矩" |
| 浏览器（客户端） | 顾客 |
| 服务器 | 后厨 |
| 请求（Request） | 顾客点菜 "来一份宫保鸡丁" |
| 响应（Response） | 服务员端菜 "您的宫保鸡丁" |
| 无状态 | 服务员记不住你上次点了什么，每次都是新客人 |

## 三、练习题

**Q1**：HTTP 的工作模式叫什么？必须是哪一方先说话？

**Q2**："无状态"是什么意思？举个例子说明它带来的问题。

**Q3**：你在 `http://localhost:8080/hello` 访问时，你的浏览器发出了什么，服务器又返回了什么？

<details>
<summary>点击查看答案</summary>

**A1**：叫**请求-响应模式**。必须是**浏览器（客户端）**先发请求，服务器才能响应，服务器不会主动找浏览器。

**A2**：无状态就是服务器不记得你之前的操作。比如你登录淘宝后点"我的订单"，服务器不认识你了，需要重新验证身份。这个问题后面由 Cookie/Session/JWT 解决。

**A3**：
- 浏览器发了一个 **HTTP 请求**：`GET /hello`
- 服务器返回了一个 **HTTP 响应**：状态码 `200`，内容为 `"hello world"`

## 四、一句话总结

> **HTTP 是浏览器和服务器之间"你问我答"的对话规则——浏览器先发请求，服务器再返回响应，每次对话都是独立的，服务器记不住你是谁。**
