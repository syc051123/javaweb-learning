## 一、创建线程的4种方式

### 方式1：继承 Thread 类

```java
// 第1步：创建一个类，继承 Thread
public class MyThread extends Thread {
    // 第2步：重写 run() 方法，写上线程要执行的代码
    @Override
    public void run() {
        System.out.println("线程执行了：" + Thread.currentThread().getName());
    }
}

// 第3步：创建对象，调用 start()
public class Test {
    public static void main(String[] args) {
        MyThread t = new MyThread();  // 创建一个线程对象
        t.start();                     // 启动线程（注意！不是调用run()）
    }
}
```

> **踩坑：** 调用 `start()` 才是启动新线程，调用 `run()` 只是普通方法调用，不会新开线程。

### 方式2：实现 Runnable 接口（推荐）

```java
// 第1步：创建一个类，实现 Runnable 接口
public class MyRunnable implements Runnable {
    // 第2步：重写 run() 方法
    @Override
    public void run() {
        System.out.println("线程执行了");
    }
}

// 第3步：创建 Thread 对象，把 Runnable 传进去
public class Test {
    public static void main(String[] args) {
        MyRunnable task = new MyRunnable();   // 创建一个任务对象
        Thread t = new Thread(task);          // 把任务交给线程
        t.start();                             // 启动线程
    }
}
```

> **为什么推荐 Runnable？**
> Java 是单继承，如果继承了 Thread 就不能再继承其他类了。
> Runnable 是接口，不影响你继承其他类。

### 方式3：实现 Callable 接口（带返回值）

```java
// Callable 和 Runnable 的区别：Callable 可以有返回值，能抛异常
public class MyCallable implements Callable<String> {
    @Override
    public String call() throws Exception {
        return "线程返回的结果";
    }
}

public class Test {
    public static void main(String[] args) throws Exception {
        // 创建任务
        MyCallable task = new MyCallable();
        // FutureTask 是用来接收线程返回结果的"容器"
        FutureTask<String> future = new FutureTask<>(task);
        // 启动线程
        new Thread(future).start();
        // 获取线程返回的结果（get() 会阻塞，直到线程执行完）
        String result = future.get();
        System.out.println(result);  // 输出：线程返回的结果
    }
}
```

### 方式4：线程池（企业开发最常用）

```java
// 企业开发不会手动 new Thread()，而是用线程池来管理线程
// 线程池的好处：不用反复创建/销毁线程，节省资源

// 创建固定大小的线程池（池子里有3个线程）
ExecutorService pool = Executors.newFixedThreadPool(3);

// 提交任务给线程池
pool.submit(() -> {
    System.out.println("任务1执行了");
});

pool.submit(() -> {
    System.out.println("任务2执行了");
});

// 注意：用完要关闭线程池
pool.shutdown();  // 不再接收新任务，已有的任务执行完就关闭
```

## 二、线程安全问题

### 问题是怎么产生的？

```java
// 两个线程同时给一个变量加1，预期结果是20000，但往往不是
public class UnsafeDemo {
    private static int count = 0;  // 共享变量

    public static void main(String[] args) throws Exception {
        // 创建两个线程，各自对 count 加10000次
        Thread t1 = new Thread(() -> {
            for (int i = 0; i < 10000; i++) {
                count++;  // 这行代码不是原子操作！
            }
        });
        Thread t2 = new Thread(() -> {
            for (int i = 0; i < 10000; i++) {
                count++;
            }
        });

        t1.start();
        t2.start();
        t1.join();  // 等待t1执行完
        t2.join();  // 等待t2执行完

        System.out.println("最终结果：" + count);
        // 大概率不是20000，可能只有10000多
    }
}
```

> **为什么结果不对？**
> `count++` 实际上分三步执行：
> 1. 从内存读取 count 的值
> 2. 把值加 1
> 3. 把新值写回内存
>
> 如果两个线程同时读到 count=0，都加 1，都写回 1，那就只加了 1 次而不是 2 次。

### 解决方法：synchronized 关键字

```java
// 给方法加锁：同一时刻只有一个线程能进入这个方法
private static synchronized void increment() {
    count++;  // 现在这一步是安全的了
}

// 或者用同步代码块（更精确，只锁必要的代码）
private static final Object lock = new Object();  // 锁对象

private static void increment() {
    synchronized (lock) {  // 只有拿到锁的线程才能进来
        count++;
    }  // 出了这个括号自动释放锁
}
```

### 解决方法：Lock 接口

```java
// 更灵活的锁，可以手动控制加锁和释放
private static final Lock lock = new ReentrantLock();

private static void increment() {
    lock.lock();     // 加锁
    try {
        count++;     // 安全操作
    } finally {
        lock.unlock(); // 一定要释放锁（放 finally 里确保执行）
    }
}
```

## 三、线程池详解（面试重点）

### 线程池的7个核心参数

```java
ThreadPoolExecutor executor = new ThreadPoolExecutor(
    2,              // corePoolSize：核心线程数（池子里一直保持的线程数）
    5,              // maximumPoolSize：最大线程数（忙的时候最多能扩到多少）
    60,             // keepAliveTime：空闲线程存活时间（超过这个时间没任务就回收）
    TimeUnit.SECONDS, // 时间单位
    new LinkedBlockingQueue<>(10), // 任务队列（排队的任务最多能放10个）
    Executors.defaultThreadFactory(), // 线程工厂（创建线程的方式）
    new ThreadPoolExecutor.AbortPolicy() // 拒绝策略（队列满了怎么办）
);
```

### 拒绝策略（面试常考）

| 策略 | 说明 |
|------|------|
| `AbortPolicy` | 直接抛异常（默认） |
| `CallerRunsPolicy` | 谁提交的任务谁自己去跑 |
| `DiscardPolicy` | 直接丢掉新任务 |
| `DiscardOldestPolicy` | 丢掉最旧的任务 |

### 线程池的工作流程

```
来了一个新任务：
  ① 当前线程数 < 核心线程数？ → 创建新线程执行
  ② 任务队列没满？ → 放到队列里排队
  ③ 当前线程数 < 最大线程数？ → 创建新线程执行
  ④ 队列也满了，线程也到上限了 → 执行拒绝策略
```

## 四、volatile 关键字

```java
// volatile 的作用：保证变量的可见性
// 什么意思？就是 A 线程改了值，B 线程马上能看到

private volatile boolean flag = false;

// 线程1
flag = true;  // 修改了flag

// 线程2
if (flag) {   // 加了volatile，这里能立即看到线程1的修改
    // 执行操作
}
```

> **不加 volatile 会怎样？**
> 线程1改了 flag，但线程2可能还在用自己缓存里的旧值（一直以为 flag 是 false）。
> volatile 强制线程每次都从主内存读，不缓存。

## 五、面试高频题

### 1. sleep() 和 wait() 有什么区别？

| | sleep() | wait() |
|------|---------|--------|
| 属于谁 | Thread 类的静态方法 | Object 类的方法 |
| 释放锁 | ❌ 不释放锁 | ✅ 释放锁 |
| 怎么唤醒 | 时间到了自动醒 | 需要 notify() / notifyAll() |
| 用法 | `Thread.sleep(1000)` | `obj.wait()` |

### 2. start() 和 run() 有什么区别？

- `start()`：启动新线程，JVM 自动调用 run() ✅
- `run()`：只是普通方法调用，不会开新线程 ❌

### 3. synchronized 和 Lock 有什么区别？

| | synchronized | Lock |
|------|------------|------|
| 用法 | 关键字，自动加锁释放锁 | 手动 lock() / unlock() |
| 灵活性 | 低 | 高（可以尝试获取锁、设置超时） |
| 性能 | 一般 | 更好（尤其高并发场景） |
| 推荐 | 简单场景用 | 复杂场景用 |

---

## 📌 重点总结

1. 创建线程：Runnable > Thread（推荐 Runnable）
2. 线程安全用 synchronized 或 Lock
3. 企业开发用线程池（Executors），不要手动 new Thread()
4. volatile 保证可见性，不保证原子性
5. sleep 不释放锁，wait 释放锁
