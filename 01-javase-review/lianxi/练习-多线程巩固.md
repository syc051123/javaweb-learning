## 一、选择题（答案附解析）

### 1. 启动一个新线程应该调用哪个方法？

A. run()
B. start()
C. execute()
D. begin()

> **答案：B**
>
> **解析：**
> 这题考的是最基本的区分。
> - `start()`：告诉 JVM 创建一个新线程，JVM 会自动调用 run() ✅
> - `run()`：只是普通方法调用，不会开新线程 ❌
>
> 想象你有一台机器（线程），start() 是按"开机键"开机，run() 只是用手去拨动零件，机器根本没有启动。

### 2. 以下哪种方式创建线程最推荐？

A. 继承 Thread 类
B. 实现 Runnable 接口
C. 直接 new Thread()
D. 以上都可以，没有区别

> **答案：B**
>
> **解析：**
> 推荐 Runnable 的原因很简单：Java 是**单继承**的。
> 如果你继承了 Thread，就不能再继承别的类了。
> 而 Runnable 是接口，不影响你继承其他类，更灵活。
>
> 企业开发中最常用的是第4种方式——**线程池**，但"创建线程的方式"这个题目考的是 Thread/Runnable/Callable 这三种。

### 3. 以下代码运行后，最终 count 的值可能小于 20000 吗？

```java
private static int count = 0;

public static void main(String[] args) throws Exception {
    Thread t1 = new Thread(() -> {
        for (int i = 0; i < 10000; i++) count++;
    });
    Thread t2 = new Thread(() -> {
        for (int i = 0; i < 10000; i++) count++;
    });
    t1.start();
    t2.start();
    t1.join();
    t2.join();
    System.out.println(count);
}
```

A. 不可能，肯定是 20000
B. 可能小于 20000
C. 可能大于 20000
D. 一定会报错

> **答案：B**
>
> **解析：**
> 这就是典型的**线程安全问题**。
> `count++` 不是原子操作，它分三步：读取→加1→写回。
>
> 举例说明：
> - 线程A和线程B同时读到 count=5
> - 线程A加1变成6，写回
> - 线程B也加1变成6，写回
> - 明明加了2次，但结果只加了1次！
>
> 解决方法：用 `synchronized` 或 `Lock` 保证同一时刻只有一个线程操作 count。

### 4. synchronized 和 Lock 的区别，哪个说法正确？

A. synchronized 需要手动释放锁
B. Lock 需要手动释放锁
C. synchronized 比 Lock 更灵活
D. Lock 不需要释放锁

> **答案：B**
>
> **解析：**
> - `synchronized`：关键字，用完后**自动释放锁** ✅ 方便但不够灵活
> - `Lock`：需要手动 `lock()` 和 `unlock()`，更灵活（可以设置超时、尝试获取锁）
>
> 注意：用 Lock 一定要在 finally 里释放锁，否则锁没释放会导致死锁！
> ```java
> lock.lock();
> try {
>     // 操作共享资源
> } finally {
>     lock.unlock();  // 确保一定释放锁
> }
> ```

### 5. sleep() 和 wait() 的区别，哪个说法正确？

A. sleep() 会释放锁，wait() 不会
B. sleep() 不会释放锁，wait() 会释放锁
C. 两者都会释放锁
D. 两者都不会释放锁

> **答案：B**
>
> **解析：**
> - `sleep()`：Thread 的静态方法，让线程睡一会儿。**睡着的时候手里还拿着锁不松手**。
> - `wait()`：Object 的方法，让线程进入等待。**会主动释放锁**，等别人 notify 再醒来拿锁。
>
> 生活中的例子：
> - sleep：你在工位上睡着了，但手里的文件（锁）还死死抓着不放
> - wait：你把文件（锁）放到桌上，去休息室等着，同事叫你（notify）再回来拿

### 6. volatile 关键字的作用是什么？

A. 保证原子性
B. 保证可见性
C. 保证有序性
D. 以上都是

> **答案：B**
>
> **解析：**
> volatile 只保证**可见性**——一个线程改了值，其他线程能立即看到。
> 它**不保证原子性**（比如 count++ 的问题用 volatile 解决不了，还得用 synchronized）。
>
> 打个比方：
> - volatile = 老师上课喊话，全班同学都能听到（可见性）
> - synchronized = 只有拿到麦克风的人才能说话（原子性）
>
> volatile 典型使用场景：**开关标志位**
> ```java
> private volatile boolean running = true;  // 控制线程停止的标志
>
> // 线程1：一直跑，直到 running 被设为 false
> while (running) {
>     // 干活
> }
>
> // 线程2：修改 running，让线程1停止
> running = false;  // 加了 volatile，线程1马上就能看到
> ```

## 二、代码分析题

### 7. 这段代码有什么问题？

```java
public class Test {
    public static void main(String[] args) {
        Thread t = new Thread(() -> {
            System.out.println("线程执行了");
        });
        t.run();  // 这里！
    }
}
```

> **答案：** 调用的是 `run()` 而不是 `start()`，所以不会新开线程，只是普通方法调用。
>
> **解析：**
> 这是新手最容易犯的错误之一。
> `run()` 只是执行线程里的代码，但还是在**主线程**里执行的，没有起到多线程的效果。
> 改成 `t.start()` 才能创建新线程。
>
> **踩坑提示：**
> 面试官经常问："我调了 run() 为什么没启动新线程？"——答案就是 run() 不是 start()。

### 8. 这段代码会不会出现线程安全问题？为什么？

```java
public class Test {
    private static int count = 0;

    public static synchronized void increment() {
        count++;
    }

    public static void main(String[] args) throws Exception {
        Thread t1 = new Thread(() -> {
            for (int i = 0; i < 10000; i++) increment();
        });
        Thread t2 = new Thread(() -> {
            for (int i = 0; i < 10000; i++) increment();
        });
        t1.start();
        t2.start();
        t1.join();
        t2.join();
        System.out.println(count);  // 结果一定是 20000 吗？
    }
}
```

> **答案：** 结果是 20000，不会有线程安全问题。
>
> **解析：**
> `synchronized` 关键字保证了 `increment()` 方法**同一时刻只能有一个线程执行**。
> 线程A在执行 increment() 时，线程B必须在外面等着。
> 所以 count++ 不会出现"两个线程同时读"的情况。
>
> 就像只有一个厕所（锁），A进去了，B只能在门口等，A出来锁释放了，B才能进去。

## 三、简答题

### 9. 线程池的7个核心参数分别是什么？各自什么意思？

> **答案：**
>
> | 参数 | 说明 | 类比 |
> |------|------|------|
> | corePoolSize | 核心线程数（一直活着的线程） | 餐厅的固定厨师 |
> | maximumPoolSize | 最大线程数 | 最多能请多少个厨师 |
> | keepAliveTime | 空闲线程存活时间 | 临时工多久没活干就辞退 |
> | unit | 时间单位 | 秒/分/时 |
> | workQueue | 任务队列（排队的任务） | 顾客排队等位 |
> | threadFactory | 线程工厂（怎么创建线程） | 怎么招聘厨师 |
> | handler | 拒绝策略（满了怎么办） | 客满了怎么处理 |

### 10. 描述一下线程池处理一个新任务的完整流程

> **答案：**
>
> 来了一个新任务：
> 1. 当前线程数 < 核心线程数？ → 直接创建新线程执行
> 2. 任务队列没满？ → 放到队列里排队等着
> 3. 当前线程数 < 最大线程数？ → 创建新临时线程执行
> 4. 都满了 → 执行拒绝策略
>
> 这个过程像银行办业务：
> - 先看柜台（核心线程）有没有空的 → 有就直接办
> - 柜台满了去排队（任务队列） → 队没满就排着
> - 队也满了开临时窗口（最大线程） → 开更多柜台
> - 所有窗口都满了 → 告诉客户"今天办不了了"（拒绝策略）
