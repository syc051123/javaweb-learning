# 线程池 - 专项强化

> 目标：彻底搞懂线程池，面试能讲清楚，开发能写对

---

## 一、为什么要用线程池？

### 不用线程池的后果

```java
// 错误示范：来一个任务就 new 一个线程
for (int i = 0; i < 1000; i++) {
    new Thread(() -> {
        System.out.println("处理任务...");
    }).start();
}
// 问题：创建1000个线程，内存爆了，CPU 全耗在创建线程上了
```

### 线程池的好处

| 好处 | 说明 |
|------|------|
| 1. 复用线程 | 不用每次都创建新线程，省时间省内存 |
| 2. 控制并发数 | 防止无限创建线程把系统搞崩 |
| 3. 统一管理 | 可以监控线程状态、统计任务执行情况 |

> 一句话：线程池就像**共享单车**，用完还回去，下一个骑的人直接用，不用每人都造一辆新车。

## 二、线程池的核心参数（面试重点，必背！）

```java
ThreadPoolExecutor executor = new ThreadPoolExecutor(
    2,                 // ① corePoolSize：核心线程数
    5,                 // ② maximumPoolSize：最大线程数
    60,                // ③ keepAliveTime：空闲存活时间
    TimeUnit.SECONDS,  // ④ unit：时间单位
    new LinkedBlockingQueue<>(10), // ⑤ workQueue：任务队列
    Executors.defaultThreadFactory(), // ⑥ threadFactory：线程工厂
    new ThreadPoolExecutor.AbortPolicy() // ⑦ handler：拒绝策略
);
```

### 逐个拆解，用餐厅例子理解

想象你开了一家**餐厅**：

| 参数 | 餐厅里的含义 | Java 里的含义 |
|------|-------------|--------------|
| **corePoolSize = 2** | 餐厅固定雇了2个厨师 | 池子里一直保持2个线程 |
| **maximumPoolSize = 5** | 最多能请5个厨师（忙的时候加3个临时工） | 线程最多能扩到5个 |
| **keepAliveTime = 60秒** | 临时工60秒没活干就辞退 | 超出核心线程数的空闲线程60秒后回收 |
| **workQueue = 10个座位** | 餐厅里最多能排10个等位的客人 | 等待队列最多存10个任务 |
| **handler = 拒绝策略** | 人太多了坐不下怎么办 | 队列满了、线程也满了，怎么办 |

## 三、线程池处理任务的完整流程（必背！）

### 流程图

```
来了一个新任务
    │
    ├──→ 当前线程数 < 核心线程数？
    │       │
    │       └──→ 是 → 创建新线程执行任务
    │
    ├──→ 任务队列没满？
    │       │
    │       └──→ 是 → 放到队列里排队等待
    │
    ├──→ 当前线程数 < 最大线程数？
    │       │
    │       └──→ 是 → 创建新临时线程执行任务
    │
    └──→ 都满了 → 执行拒绝策略
```

### 逐步案例

假设线程池配置：core=2, max=5, 队列容量=3

```
来了第1个任务：线程数0 < 核心2 → 创建线程A执行 ✅
来了第2个任务：线程数1 < 核心2 → 创建线程B执行 ✅
来了第3个任务：线程数2 = 核心2，不放队列里 → 队列未满 → 放入队列 ✅
来了第4个任务：放入队列 ✅
来了第5个任务：放入队列 ✅
来了第6个任务：队列已满（3个），线程数2 < 最大5 → 创建线程C执行 ✅
来了第7个任务：队列已满，线程数3 < 最大5 → 创建线程D执行 ✅
来了第8个任务：队列已满，线程数4 < 最大5 → 创建线程E执行 ✅
来了第9个任务：队列已满，线程数5 = 最大5 → 执行拒绝策略 ❌
```

## 四、4种拒绝策略（面试常考）

| 策略 | 效果 | 生活类比 |
|------|------|---------|
| **AbortPolicy**（默认） | 直接抛异常 RejectedExecutionException | 餐厅说"不接了"并报警 |
| **CallerRunsPolicy** | 谁交的任务谁自己去做 | 老板亲自去后厨炒菜 |
| **DiscardPolicy** | 悄悄丢掉新任务，不报错 | 假装没看见这个客人 |
| **DiscardOldestPolicy** | 丢掉队列里最旧的任务，把位置让给新的 | 让最老的客人走，新客人坐 |

```java
// 四种拒绝策略的写法
new ThreadPoolExecutor.AbortPolicy()         // 抛异常（默认）
new ThreadPoolExecutor.CallerRunsPolicy()    // 调用者自己执行
new ThreadPoolExecutor.DiscardPolicy()       // 丢弃新任务
new ThreadPoolExecutor.DiscardOldestPolicy() // 丢弃最旧任务
```

## 五、Executors 工具类（快捷创建线程池）

Java 提供了 Executors 工具类，可以快速创建常见的线程池：

```java
// 1. 固定大小线程池（最常用）
ExecutorService pool = Executors.newFixedThreadPool(3);
// 特点：核心线程数 = 最大线程数 = 3，队列无限大
// 适用：任务量稳定，不会突然暴增

// 2. 缓存线程池
ExecutorService pool = Executors.newCachedThreadPool();
// 特点：核心=0，最大=Integer.MAX_VALUE，队列容量=0
// 适用：任务多但执行时间短

// 3. 单线程池
ExecutorService pool = Executors.newSingleThreadExecutor();
// 特点：只有一个线程，保证任务按顺序执行
// 适用：需要任务排队执行的场景

// 4. 定时线程池
ScheduledExecutorService pool = Executors.newScheduledThreadPool(2);
// 可以执行定时任务
pool.schedule(() -> System.out.println("延迟1秒执行"), 1, TimeUnit.SECONDS);
pool.scheduleAtFixedRate(() -> System.out.println("每2秒执行一次"), 0, 2, TimeUnit.SECONDS);
```

### 阿里巴巴开发手册的强制规定

```
【强制】线程池不允许使用 Executors 去创建，而是通过 ThreadPoolExecutor 的方式。
原因：Executors 返回的线程池都有弊端：
  - FixedThreadPool 和 SingleThreadPool：队列长度 Integer.MAX_VALUE，可能堆积大量请求导致 OOM
  - CachedThreadPool：最大线程数 Integer.MAX_VALUE，可能创建过多线程导致 OOM
```

```java
// ✅ 正确做法：手动 new ThreadPoolExecutor
ThreadPoolExecutor executor = new ThreadPoolExecutor(
    2, 5, 60, TimeUnit.SECONDS,
    new ArrayBlockingQueue<>(100),  // 有界队列，不会无限堆积
    new ThreadPoolExecutor.AbortPolicy()
);

// ❌ 错误做法：用 Executors
ExecutorService pool = Executors.newFixedThreadPool(3);
// 队列是 LinkedBlockingQueue，默认容量 Integer.MAX_VALUE
// 如果任务提交速度 > 处理速度，队列会无限增长 → 内存溢出
```

## 六、线程池的监控

```java
// 线程池提供了一些监控方法
ThreadPoolExecutor executor = new ThreadPoolExecutor(...);

// 获取当前线程数
int poolSize = executor.getPoolSize();

// 获取活跃线程数
int activeCount = executor.getActiveCount();

// 获取已完成任务数
long completedCount = executor.getCompletedTaskCount();

// 获取队列中等待的任务数
int queueSize = executor.getQueue().size();

// 打印监控信息
System.out.printf("线程数：%d，活跃：%d，已完成：%d，排队：%d%n",
    poolSize, activeCount, completedCount, queueSize);
```

## 七、完整示例：从创建到关闭

```java
public class ThreadPoolDemo {
    public static void main(String[] args) {
        // 第1步：创建线程池
        ThreadPoolExecutor executor = new ThreadPoolExecutor(
            2,                      // 核心线程数：2
            5,                      // 最大线程数：5
            60,                     // 空闲线程存活时间：60秒
            TimeUnit.SECONDS,       // 时间单位：秒
            new ArrayBlockingQueue<>(10),  // 有界队列，最多放10个任务
            Executors.defaultThreadFactory(),
            new ThreadPoolExecutor.AbortPolicy()  // 满了就抛异常
        );

        // 第2步：提交15个任务
        // 2个核心线程立刻执行 + 10个排队 + 3个临时线程 = 15个能正常处理
        // 第16个任务会被拒绝
        for (int i = 1; i <= 15; i++) {
            int taskId = i;
            executor.submit(() -> {
                System.out.println("任务" + taskId + " 由 " 
                    + Thread.currentThread().getName() + " 执行");
                try {
                    Thread.sleep(1000);  // 模拟任务执行1秒
                } catch (InterruptedException e) {
                    e.printStackTrace();
                }
            });
        }

        // 第3步：监控线程池状态
        System.out.println("线程数：" + executor.getPoolSize());
        System.out.println("队列中：" + executor.getQueue().size());

        // 第4步：关闭线程池（一定要关闭！）
        executor.shutdown();  // 不再接收新任务，已有的任务继续执行完
        // executor.shutdownNow();  // 立即关闭，正在执行的任务也被中断
    }
}
```

## 八、面试必背

### Q1：corePoolSize 和 maximumPoolSize 为什么不一样？

> 为了**节省资源**。平时任务少的时候只保持 core 个线程，流量高峰期才临时扩容到 maximum。

### Q2：队列为什么要有界？

> 无界队列（如 `LinkedBlockingQueue` 默认容量无限）会导致任务无限堆积，最终内存溢出（OOM）。
> 有界队列能限制等待的任务数量，超过就触发拒绝策略，保证系统不会崩溃。

### Q3：submit() 和 execute() 有什么区别？

| | execute() | submit() |
|--|----------|---------|
| 返回值 | 无 | 返回 Future，可以获取结果 |
| 异常处理 | 线程内自己处理 | 可以通过 Future.get() 捕获异常 |
| 推荐 | 不关心结果时用 | 需要返回值或异常时用 |

### Q4：怎么合理设置线程池大小？

```
CPU密集型任务（计算多）：线程数 = CPU核数 + 1
IO密集型任务（读写多）：线程数 = CPU核数 × 2
```

> 因为 CPU 密集型一直在算，线程多了反而来回切换浪费性能。
> IO 密集型经常在等读写，多开几个线程让 CPU 不等闲。

## 总结

```
线程池 = 核心线程(core) + 排队队列(queue) + 临时线程(max) + 拒绝策略(handler)

核心线程：一直活着
临时线程：忙的时候帮忙，闲了回收
任务队列：排队的缓冲区
拒绝策略：全满了怎么办

记住餐厅的例子：
2个固定厨师 → 客人多了排队 → 队满了请临时工 → 还是忙不过来就赶客
```
