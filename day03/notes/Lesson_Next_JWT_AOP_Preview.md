## 🎫 模块一:登录认证(JWT)——"电影票"的故事

### 现在的问题

**任何接口谁都能调。**

```
现在:  GET /emps          ← 不登录也能查!谁都能调,没"你是谁"的概念
```

前端想查员工就查,想删就删——**服务器分不清请求是真是假**。就像电影院**不查票**,谁都能进 → 乱套。

### JWT 的解决思路:发一张"电影票"

```
第1步 登录
  用户输入账号密码 → 服务器验证对了 → 发一张【令牌(JWT)】

第2步 带票请求
  以后每次请求都带上这张票(放在请求头)
  → 服务器验证票有没有效 → 有效才放行

第3步 拦截器查票
  没票 / 票过期 → 拦下来,不许进
```

**核心类比:JWT = 电影票 🎫**

| JWT 概念 | 生活中的电影票 |
|---------|--------------|
| JWT 令牌 | 那张票 |
| 登录时发 | 门口售票 |
| 每次请求带上 | 进场出示票据 |
| 拦截器验证 | 检票员查票 |
| 过期作废 | 票有时效 |

### 你要学的新知识点(先混个脸熟)

| 知识点 | 一句话 |
|--------|--------|
| **JWT** | 一串加密的令牌,登录后发给前端 |
| **拦截器(Interceptor)** | 请求进 Controller 前"查票",没票拦下 |
| **登录接口 POST /login** | 验证账号密码,发令牌 |
| **BCrypt 密码加密** | 存的是加密后的密码,不存明文(你加了依赖,还没用) |

### 为什么这个最难也最值钱

- **面试必问**:"JWT 是什么?和 Session 有什么区别?"是后端高频题
- **几乎所有系统都要**:管理后台、App、小程序登录都靠它

## 🪄 模块二:AOP 日志——"自动帮你记日记"

### 现在的问题

你每个 Controller 方法都手动写 `log.info(...)`:

```java
log.info("查询所有部门");
log.info("新增部门{}", dept);
log.info("删除部门{}", id);
```

**10 个接口写 10 遍,100 个写 100 遍——太累了!**

### AOP 的解决思路:写一次,自动给所有方法加日志

```
你只写一次"切面逻辑"
  → 框架自动在【每个方法】执行前记录"开始"
  → 执行后记录"结束 + 耗时"
  → 不用每个方法都手动写 log
```

**核心类比:AOP = 给所有方法"包一层壳" 🪄**

```
原方法:  doSomething()
AOP包一层后:  [开始] doSomething() [结束,耗时50ms]
```

### 你要学的新知识点

| 知识点 | 一句话 |
|--------|--------|
| **AOP(面向切面)** | 不改原代码,在方法外"插一脚" |
| **@Aspect** | 标记"这是切面类" |
| **@Around** | 方法执行前后都插入逻辑(记录开始/结束/耗时) |

### 其实你已经在用 AOP 了

- **PageHelper** 就是 AOP——它拦截你的查询,偷偷加 LIMIT
- **Spring 事务**也是 AOP
- 你只是没意识到,这次是学会"自己写一个"
